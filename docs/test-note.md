# Nautilus Log 测试 · 方案 5

> **新写法**：```nautilus``` 块里放**当天的配置覆盖**（空着＝用全局设置），
> 计划写在块**下面**、作为普通 Markdown —— **始终可编辑、可拖拽换序**。
> **计划止于第一个空白行。**
> **块语言 `nautilus` 和 `naut` 都认**，后者短一点好敲。

---

## 1. 基本（空块＝全用全局设置）

```nautilus
```
- 05:00-06:00 晨间routine
- [ ] 写项目简报 45m
- [ ] 过一遍笔记 30m
- 11:45-12:30 午饭
- [ ] 回邮件

**这一段就在边界外了**，不会被算进上面的计划。

---

## 2. 🔑 当天覆盖工作时段（这是新能力）

```nautilus
start: 09:00
end: 02:00
```
- 21:00-22:00 晚饭
- [ ] 夜间深度工作 2h
- [ ] 收尾 30m

预期：窗口变成 09:00→次日 02:00（一个连续 1020 分钟窗口），**不用去改全局设置**。

## 9. 钉住开始时刻（不用写完整区间）

```naut
```
- [ ] 09:00 写周报 30m
- [ ] 9am 早会 45m
- [ ] 2pm 下午会 1h
- [ ] 14:30 复盘
- [ ] 普通弹性任务 45m
- [ ] 读第 9 章 30m

预期：
- 前四条是**钉死的事件**（黄色）：09:00–09:30、09:00–09:45、14:00–15:00、
  14:30–14:45（没写时长 → 用默认时长）
- 后两条是**弹性任务**（蓝色）
- 🔴 `读第 9 章` 里的「9」**不能**被当成 09:00 —— 裸数字不算时刻，
  必须写 `9:00` 或 `9am` 才表达时刻意图

---

## 10. 已完成任务为什么不见了

```naut
```
- [x] 已完成但没记完成时刻 40m
- [ ] 未完成的任务 30m

预期：`- [x]` 那条**不会出现在盘上**，容量也只算未完成的 30m。
引擎不知道它几点做完，就拒绝编造历史（"does not invent history"）。

---

## 11. 已完成 + 完成时刻锚点

```naut
```
- [x] 学术社交 40m d11:20
- [x] Nautilus Log 插件 40m d13:00
- [ ] 出门 30m

预期：前两条画成**灰色历史切片**（10:40–11:20、12:20–13:00），带删除线；
容量只算未完成的 30m。

💡 不用手敲锚点：把光标放在任务行，`Cmd+P` → **勾选并打完成时间戳**
（默认没有快捷键，可在 设置 → 快捷键 里自己绑）。
