# Nautilus Log 使用指南

> 本指南描述**本仓库实际实现**的行为，每一条都对着 `src/` 核对过。
> 与 Roam 原版的有意差异汇总在文末「与上游的差异」。

## 计划格式

一个 Nautilus Log 由两块组成：

- **块**（```nautilus ``` 全名或 ```naut ``` 短别名）：放**当天的配置覆盖**，
  空块＝完全沿用全局设置。
- **计划正文**：写在块**下面**的普通 Markdown 列表，**止于第一个空白行**。

````markdown
```naut
start: 09:00
end: 02:00
default-duration: 30
```
- 08:30-09:30 起床
- [ ] 写周报 45m
- [ ] 回邮件
- [ ] 09:00 开站会 30m
````

计划正文始终是可编辑、可拖拽换序的原生 Markdown，也进 Obsidian 全局索引
（Tasks / Dataview 都能看到）。块内配置只认这些键，写错会给出 ⚠ 警告而不是静默忽略：

| 键 | 含义 |
| --- | --- |
| `start` / `start-time` / `workday-start` | 当天开始小时（0–23） |
| `end` / `end-time` / `workday-end` | 当天结束小时（1–24；≤ start 即跨午夜） |
| `default-duration` / `todo-duration` | 无时长任务的默认分钟数 |
| `legend-length` / `desc-length` | 图例文字截断宽度 |
| `urgent` / `urgent-trigger` | ⚠ 设置项存在，但当前实现**不改颜色**（见设置表） |
| `language` / `lang` | `en` / `zh` |

**行的种类**（行序就是优先级，永不排序）：

- **固定事件**：带时间区间的行。`12:30-14:00`、`9 to 10:45` 都行；带不带复选框都
  可以——`- [ ] 09:00-10:00 站会` 是可勾掉的固定事件。
- **钉住开始时刻**：只写一个开始时刻的任务，`- [ ] 09:00 写周报 30m` → 09:00–09:30；
  不写时长就用默认时长。⚠️ **裸数字不算时刻**——`读第 9 章` 里的「9」不会被当成
  09:00；要表达时刻请写 `9:00` 或 `9am`。
- **弹性任务**：未勾选、也没有任何时钟时刻的任务，流进剩余时间。
- 时长写法：`30m` / `30min` / `1h` / `1h30m`。
- 事件行推荐写成 `- 08:30-09:30 起床`（与 `- [ ]` 在阅读模式下缩进一致）；裸文本
  也接受。

**嵌套子任务不参与排程**。比首行更深的缩进行会被跳过（与上游只读「直接子块」一致）。
原因值得说清：子任务是「怎么做」，父任务才是「排什么」——平铺会把父子需求重复计入
（父 60m + 子 20m + 子 20m 会变成 100m），而且树的优先级有歧义。

**已完成任务需要完成时刻锚点**：`- [x] 学术社交 40m d11:20` 才能画成历史切片；没有
锚点的已完成任务仍算完成（不再消耗容量），但盘上画不出来——引擎拒绝编造它没有被
告知的历史。不想手敲锚点，就用命令 **勾选并打完成时间戳**。

## 排程规则

1. 固定事件先占自己的时间区间。重叠事件按**并集**算，一分钟不重复计。
2. 未完成的弹性任务按书写顺序读取。
3. 从**当前时刻**起，任务填进下一个足够大的连续空档。
4. 时间流逝把未完成工作往前推，**不改变优先级**。
5. 到结束时刻仍放不下的任务进「今日放不下 / Unscheduled today」，绝不被静默丢弃。

调度是确定性的：任务是原子的，塞不进一个空档就去找下一个，**不会拆开**。整个窗口
可以跨午夜——如 21:00–次日 02:00 是一个连续窗口。

## 头部指标

| 指标 | 含义 |
| --- | --- |
| Planned | 剩余弹性需求；其右侧的百分比 = 剩余可安排 ÷ 全天可安排 |
| Remaining / Overload / No fitting slot | 状态三态，见下 |
| Available | 弹性时间：当前剩余 / 全天总额；当前分钟在烧它时带火焰标记 |
| Events | 固定事件时间：当前剩余 / 全天总额；当前分钟在烧它时带火焰标记 |

状态三态的区别：

- **Remaining（余量）**：时间够，还有富余。
- **Overload（超载）**：需求总量超过可安排时间——时间不够，再怎么挤空档也塞不下。
- **No fitting slot（没有连续空档）**：总时间够，但没有任何一个连续空档装得下某个
  任务（碎片化）。与 Overload 的本质区别是**总量**：No fitting slot 是「有地但装不
  下」，Overload 是「根本没那么多地」。

火焰标记指示当前这一分钟在消耗 Available 还是 Events。事件区间是**半开区间**：
恰好落在事件结束的那一分钟属于 Available。

## 视觉语义

| 颜色 | 含义 |
| --- | --- |
| 蓝 | 弹性任务 |
| 黄 | 固定事件 |
| 灰（带删除线） | 已完成的记录（历史切片） |
| 红针 | 当前时刻 |
| 斜纹 / 变暗 | 已流逝但没被记录的空档 |

过去的空档是**事实性排程数据**，不是「时间被浪费」的判断。

## 图表控制

图表上方三个按钮：

- **眼睛**：显示 / 隐藏已完成项。
- **播放**：从窗口起点回放到当前时刻后自动停止。纯视觉，**绝不写回 Markdown**。
- **折叠**：只藏图，容量指标与计划文本仍可见；折叠状态按块记住（localStorage）。

## 悬停提示

把鼠标悬停（或键盘聚焦）在任务 / 事件切片上，会看到它的标题、准确区间和时长。
切片本身带 `tabindex` / `role` / `aria-label`，所以键盘可达。窄容器（侧栏等紧凑
模式）为了不裁切浮层，不挂悬停提示。

## 侧栏

右侧栏有一个 Nautilus Log 视图（`nautilus-log-view`）：把今天 Daily Note 的
**第一个** nautilus 块的计划画成容量头 + 螺旋，不用打开笔记就能看到今天这盘菜。

- 每分钟 tick 一次；主计划文件改动时重渲染。
- 没有今日笔记 / 没有 nautilus 块 → 明说「no plan for today」，绝不静默画空盘。

## 执行层

执行层默认**关闭**。设置里的总开关 **Actual time tracking** 打开后，其余 4 项执行层
设置才出现。

- **Primary Plan**：今天 Daily Note 里第一个 `nautilus` 块之后的计划，是执行层读写
  的那份计划。
- **Timing / Plan / Review** 三个视图：
  - **Timing**：当前 Timing Line + 最近闭合的任务
  - **Plan**：Primary Plan 里未完成的直接子任务
  - **Review**：今天的 Planned vs Actual，逐任务状态为 compared / not-tracked /
    live / paused / not-started

**CLOCK / LOGBOOK 形态**。实际时间以 Org 风格 CLOCK 记录写进任务下方的
`LOGBOOK::` 抽屉：

```markdown
- [ ] 写周报 45m
    - LOGBOOK::
        - CLOCK: [2026-08-24 Mon 10:00]--[2026-08-24 Mon 10:18] => 0:18
```

- 首次对某任务 Clock In 时若没有抽屉会自动创建。
- 未闭合的 CLOCK 只有开始戳：`CLOCK: [2026-08-24 Mon 10:00]`。
- **只有未完成的任务能拥有 Timing Line**；已完成任务 Clock In 会被拒绝。
- **同一时刻只有一个 CLOCK**。切换任务会先合上上一个、再在同一瞬间开下一个。
- 每一次写回都**按内容校验**目标行，不匹配就放弃而不是乱写（见「数据与安全」）。

**Recent**：Timing 视图里「最近」保留 45 分钟（Recent retention minutes，`0` = 关闭）。

**POMO（番茄钟）**：

- 任务在计时时，达到 Pomodoro minutes 阈值只把信号变红——**绝不停止工作**。
- 没有任何任务 CLOCK 在跑时，面板表头可启动**独立番茄钟**（正计时）：它**不写任何
  块**，也不影响 Actual / Planned / Review / 螺旋；一旦开始任务 CLOCK，独立番茄钟
  立即被清除——CLOCK 永远优先。

**忘关警告**：计时器跑得超过 Forgotten timer warning minutes（默认 120 分钟）时
只出现「Check CLOCK」警告，**绝不自动停止或删除 CLOCK**。`0` = 关闭。

**历史**：

- 未完成任务按 Planned 预估排程。
- 已完成任务需要 `dHH:MM` 完成锚点才能画出来；切片从锚点往回推预估时长。
- 执行层的 Review 视图用 CLOCK 实际时间与 Planned 对比，**Actual 不受 Planned 封顶**。
- 同一条任务的多段 CLOCK 在 `LOGBOOK::` 里分开存。
- 没有实际时间或完成锚点，引擎**不编造历史**。

## 设置（11 项）

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| Language | English | 界面文案语言（en / zh） |
| Workday start hour | 5 | 0–23，窗口开始小时 |
| Workday end hour | 21 | 1–24；≤ start 即「次日」 |
| Description length | 22 | 15–30，图例截断宽度 |
| Default task duration | 15 | 5–60，无时长任务的默认分钟 |
| Urgent trigger | 空 | ⚠ 设置项存在，但当前实现不改颜色（只存配置） |
| Actual time tracking | 关 | 执行层总开关；关着时以下 4 项隐藏 |
| Timing line in sidebar | 开 | Clock In 时把当前任务钉到右侧栏 |
| Pomodoro minutes | 45 | 到点只变信号、不停止工作；`0` 会被当作未设置回落到 45 |
| Recent retention minutes | 45 | Recent 保留多久；`0` = 关闭 |
| Forgotten timer warning minutes | 120 | 忘关警告阈值；`0` = 关闭；只警告不停止 |

## 命令一览

命令面板里有：

- **Complete task with timestamp / 勾选并打完成时间戳**——勾选当前任务行并追加
  `dHH:MM` 完成锚点。默认不绑快捷键，可在 设置 → 快捷键 自行绑定。
- **Create Nautilus Log test note / 创建 Nautilus Log 测试笔记**——生成一份带测试
  场景的笔记。
- **Open Nautilus Log settings**——打开设置。

执行层开启后，执行层面板还提供这些动作：Clock In / Clock Out、Complete task（勾选
完成）、Delete current CLOCK（再次点击确认）、Start / Stop standalone POMO、Locate
Primary Nautilus。

## 数据与安全

- 实际时间就是笔记里的普通 Markdown（Org 风格 CLOCK），不是外部数据库。
- 写回前**先校验目标行内容**：与你看到的不一致就放弃并报错，绝不猜着写（防止
  Obsidian 在你之后写、覆盖你的改动）。
- 文件正被编辑器打开 → 走 Editor API，与你的在编辑改动合并；否则走 `vault.process`
  原子读改写。
- 行号会随编辑漂移，写回一律**按内容定位**，且只接受唯一匹配。
- 卸载插件不会重写或删除你的块。

## 与上游的有意差异

1. **块格式**：上游是「组件 + 直接子块」（Roam 有块树）；本移植用 ```nautilus ``` /
   ```naut ``` 代码块放当天配置覆盖，计划写在块下面、止于第一个空白行（Obsidian
   代码块只有兄弟行、没有子块）。
2. **按天覆盖工作时段**是本移植新增的（上游只有全局设置，块参数只是 fallback）。
3. **单个开始时刻可钉住任务**（上游必须写完整区间）；裸数字不算时刻。
4. **已完成任务需 `dHH:MM` 锚点**才画得出来；本移植新增命令「勾选并打完成时间戳」
   （上游靠外部 Todo Trigger 插件）。
5. **嵌套子任务不参与排程**（与上游一致；原因见「计划格式」）。
6. **事件行推荐写 `- 08:30-09:30 起床`**（与 `- [ ]` 缩进一致）；裸文本仍接受。
